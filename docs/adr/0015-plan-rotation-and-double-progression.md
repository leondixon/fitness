# A Plan rotation designed through Claude, progressed by rule

For the first cut, the athlete trains through a Plan: a repeatable rotation of Sessions done strictly in order, not a Session generated each day (supersedes ADR-0001 for now). No LLM runs inside the app. The athlete asks Claude, on their own subscription, to research Activation and design the Plan; Claude reads and writes the app's data through an MCP server the backend exposes, and the backend validates a whole Plan before saving any of it. Load then follows double progression, a deterministic rule: +1 rep target within the rep range, one load step after every set hits the top in three Sessions in a row, one step down after two Sessions in a row below it (supersedes the Trend-based load of ADR-0008 and ADR-0011 for now; amends ADR-0014, since an LLM now designs the Plan while the prescription stays code). Daily adaptive Check-in was the alternative; it was deferred because it needs Health sync, Chat and fatigue before it can prescribe anything, and a rotation with a transparent rule delivers progressive overload now.
